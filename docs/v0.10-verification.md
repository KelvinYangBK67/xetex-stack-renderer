# XSR 0.10 release and verification

Release date: 2026-10-06. Version is **0.10**, not 0.10.0.

## What changed

The generic inline external-glyph release extends the existing vector/provider
seam. `\GlyphRegister{label}{file}` and `\Glyph[scale=...,raise=...]{label}`
accept SVG, PNG, JPEG/JPG and PDF without exposing provider configuration.
Repeated identical registration is idempotent; conflicting registration and
unknown labels fail explicitly. The global registry is only label -> file;
no aliases or semantic metadata were added.

`VisualAsset` resolution converges before `InlineGlyph` layout. The shared
model carries intrinsic canvas dimensions, payload/cache identity, normalized
canvas size, complete width, advance, baseline shift and height/depth. Manual
SVG, direct SVG, provider SVG and provider fallback geometry all use it.
Existing Egyptian/Khitan font-backed layout remains unchanged.

For ratio r=W/H, current ideographic-cell size C and uniform scale s:
`w=alpha*C*s*sqrt(r)`, `h=alpha*C*s/sqrt(r)`. Vector alpha is 1.00; image alpha
is 1.10, centralized with alignment and spacing in the policy layer. Images
center on the current ideographic cell; user raise is additional. Vectors
use the reference cell baseline and zero side bearings. Image side bearings
are -2% of canvas width per side, so advance is 96% of the unchanged canvas
width. This is intentional typographic overhang; height and depth still cover
the complete canvas and tall/wide glyphs are never hidden in a fake 1em box.

Cell metrics prefer current-font U+3000 advance and U+56FD height/depth center;
with no ideographs, use the current em square above the baseline. Scale and
raise are applied at TeX use time, so one source response supports multiple
font sizes and adjustments. No aspect-ratio clamp or anisotropic adjustment
exists. Ratios outside [1/16,16] produce a warning, retaining the proportions.

PNG/JPEG use pixel dimensions, ignoring asymmetric DPI metadata. Single-page
unencrypted PDF uses its complete MediaBox with page rotation applied. The
original file is included unchanged: no crop, trim, pixel processing, cleanup,
OCR or vector tracing. Even an existing PDF CropBox does not replace the full
MediaBox selected for inclusion. Restricted SVG becomes PGF paths; its safety
rules and importer version remain unchanged. Out-of-viewBox vector geometry
expands reported extents without changing normalization.

**Migration from 0.9:** non-square direct/provider SVG now uses geometric-mean
normalization instead of mapping design-space height to one em. Square SVG
has the same nominal size. External-backend version is `inline-0.10`, preventing
old response reuse; font-backed backend versions remain unchanged because their
layout is unchanged. Source/importer identity and provider cache metadata are
preserved. Image payloads additionally verify original file content at use.

## Repeated include repair

The initial focused commit repairs occurrence-based execution independently of
the inline feature. Source discovery caches file contents, while vector command
and missing-policy traversal execute every include occurrence. Only an active
recursion stack rejects cycles. One shared resolver prefers the current parent
then explicit input-root directories in order, never incidental visited dirs.
Provider/style/policy state follows brace scopes across includes. Tests cover
repeated child execution under different styles/policies, repeated explicit
entrypoints, path collisions, active cycles and font-run policy variants.

## Dependency and release boundaries

Runtime dependencies are fontTools, Pillow and the new **pypdf >=6,<7**
([BSD-3-Clause license](https://github.com/py-pdf/pypdf/blob/main/LICENSE)).
pypdf reads PDF page metadata without introducing a PDF renderer or external
engine. The fresh installation used pypdf 6.19.0. Pillow reads inline image
headers only; existing font ink-mask support remains separate.

No KAGE/Hieropy import, implementation or dataset is introduced. Optional
provider argv invocation, `shell=False`, revision metadata and result caching
are preserved. Providers are tested with the original synthetic fixture only.
There is no Bai-style IDS, zi.tools, GlyphWiki, IDS geometry, Han lookup,
network glyph service, IMPE integration or PDF semantic text layer.

The prior 0.9 acceptance baseline was 879 passed, 0 skipped, with 76 separate

`python -m pytest tests/test_inline.py tests/test_inline_tex.py tests/test_repeated_includes.py -ra`.

Six expected Python warning instances occur in the complete/separate suites:
two `XSR-INLINE-ASPECT` warnings for deliberate 32:1 image/vector fixtures;
two `XSR-GLYPH-MISSING` warnings for Noto Khitan U+18CFF; one missing synthetic
Egyptian U+13002; one `XSR-PROVIDER-MISSING` from the intentional missing fixture.
The focused run contains just the two aspect warnings. No tests were skipped
locally. PDF metadata checks also exercise rotated pages and original MediaBox
inclusion despite a smaller CropBox.

Integration checks measure actual TeX width/height/depth, PDF payload types and
line baselines. They cover 1:1, 1:2, 2:1, 1:4, 4:1 and 32:1; small/normal/Large;
positive and negative raise; uniform scale; a synthetic ideographic font with
non-default advance/center; one response reused across sizes; source changes;
Unicode filenames; no-shell compilation; duplicate/missing registry errors;
rejected independent dimensions; and manual/provider vector convergence.

## Showcase verification

All four current showcases rebuilt in fresh temporary directories, with final
XeLaTeX using `-no-shell-escape`:

| PDF | Pages | Verification |
| --- | --- | --- |
| `examples/inline-glyph-showcase.pdf` | 4 | Neutral original fixtures, running text, all ratios, formats, sizes and adjustments |
| `examples/egyptian-showcase.pdf` | 6 | Noto / NewGardiner / Segoe regression |
| `examples/khitan-showcase.pdf` | 5 | Noto / optional local Linear regression |
| `examples/vector-showcase.pdf` | 3 | Direct SVG, provider transport and synthetic missing glyphs |

All 18 pages were rendered with Poppler and visually inspected. No unintended
clipping, overlap or blank section was found. Vector/provider pages contain
path drawings and no raster images. Inline pages retain raster/image inclusion
and vector paths. Builders reject overfull boxes and unavailable responses;
inline/vector builders also reject missing-character warnings. The Egyptian
builder tolerates the known NewGardiner U+0020 loading warning; its document
labels remain in the text font. The Khitan builder emits its expected U+18CFF
warning, and vector/provider generation emits the three intentional missing
Khitan/Egyptian/provider diagnostics shown in that specimen.

Fixture images/PDF are drawn originally by a test helper into owned temporary
build directories, not transformed from user images or bundled in the runtime.
Only showcase PDF deliverables are committed. No font, glyph dataset, generated
response, request, cache or wheel is tracked. The historical two-page
font-metrics PDF remains the existing 0.9 artifact.

## Packaging and CI

A wheel was built from a source-only snapshot, without old build or egg-info
contents. All 31 Python files were compared byte-for-byte with working sources.
A fresh isolated environment installed only declared runtime dependencies;
verification imported and rendered native parsers, fonts, SVG and raster/PDF
metadata with KAGE/Hieropy imports blocked. The verifier asserts it is importing
from that environment, not the repository. No font or glyph asset is in the wheel.

Local wheel SHA-256:
`86d95a6588bf07da3c90fba938afd566ee532977a62ddb64d9a5499e43d0e84d`.

The [CI workflow](../.github/workflows/ci.yml) runs the full suite, separate
four-module XeLaTeX suite, all four showcase builds, artifact checks, boundaries,
and a clean 0.10 wheel installation on Ubuntu 24.04 / Python 3.11. Linux uses
Noto/NewGardiner without Windows Segoe and builds four Khitan pages without the
optional local Linear font. Final commit and observed CI status are reported
with the release completion message.

Remaining limits are explicit: restricted SVG, literal preprocessing rather
than arbitrary TeX expansion, single-frame images and single-page unencrypted
PDFs, one provider process per uncached request, no automatic image preparation,
and no semantic text layer. TeX's native dimension limits still apply.
