# XSR 1.1 verification — PDF Unicode extraction

Release implementation: [`8db7e0eb5421`](https://github.com/KelvinYangBK67/xetex-stack-renderer/commit/8db7e0eb5421b704c7963bc2515c312d73bf8cac)
(2026-10-11). This document records the 1.1 change; current usage is
documented in the [README](../README.md).

## Implemented behavior

Egyptian quadrats and Khitan Small Script clusters attach their **original
Unicode source sequences** to atomic PDF layout boxes using `/ActualText`.
The `xsrActualText` wrapper serializes a UTF-16BE source unit with a PDF
text-string byte-order mark and surrounds the drawn TeX using PDF marked
content. The backend supplies the source run for each quadrat/cluster, rather
than reconstructing text from two-dimensional glyph geometry.

The source mappings include EHFC, Khitan U+16FE4 filler, variation
selectors, and cluster separators such as U+200B where present.
Atomic spans preserve units across line breaks. Ordinary text continues
to rely on XeLaTeX/dvipdfmx `ToUnicode`.

The change adds `src/xsr/copy_text.py`, source-unit recording in the
Egyptian parser/model/backend and Khitan backend, the `xsrActualText`
TeX command, and PDF-extraction regression coverage. The selected glyph
fonts and two-dimensional layout rules remain in their respective backends.

## PDF reader boundary

PDF readers differ in `/ActualText` support; adjacent atomic units can
gain inferred spaces during selection. Decorations without an enclosing
selectable text unit may not be independently selectable. The feature
preserves the Unicode content of each atomic unit, not an exact
byte-for-byte paragraph extraction guarantee. No invisible text overlay
or general LaTeX-source capture is involved.
