# XSR 0.7 verification

XSR 0.7 replaces the Egyptian parser boundary with `xsr.egyptian.parser.EgyptianParser`.
The parser is an independent recursive-descent implementation based on
[Unicode 18 chapter 11.4.2](https://www.unicode.org/versions/Unicode18.0.0/core-spec/chapter-11/).
It produces the existing immutable `ParsedEgyptianRun` / `EgyptianNode` model;
font metrics, ink search, geometric layout, XeTeX serialization, paragraph
breaking, RTL, cache identity and preprocess dispatch remain downstream.
No Hieropy source was used as an implementation template.

Precedence is insertion > overlay > horizontal > vertical. Explicit segment
controls group recursively. H/V joins collect operands in source order;
adjacent complete expressions begin separate quadrats. Each insertion control
consumes one following sign or segment as child of the same preceding sign
core. Overlay consumes single signs or segments as its arms; the two axes
remain explicit in the XSR tree. Variation selector, mirror and damage
attach in that order to one sign.
Enclosure controls delimit their own interior sequence, with optional endpoint
signs and endpoint damage. Editorial brackets decorate adjacent horizontal
content in explicit Egyptian context and may be unbalanced.

## Baseline and compatibility

Before edits, fetched remote `main` and verified HEAD
`b6be31918e78d60a2ad4850800565f2dd1c31bb4`. The 0.6 baseline passed
576 full pytest cases and 35 separate XeLaTeX integration cases. Its six-page
showcase was rebuilt with Noto, NewGardiner and Segoe UI Historic for comparison.
No pre-existing failures were observed.

The 0.7 parser-only suite contains 133 cases: 75 direct structural/invalid-input
cases, 56 corpus cases and two API boundary cases. It tests exact tree shapes,
precedence, seven insertion slots, nested structures, enclosure families, signs and modifiers, blanks,
lost signs and editorial brackets. The regression corpus parses all 43 distinct
showcase runs plus representative nested and mixed EHFC strings. Existing
geometry and XeLaTeX assertions were retained; the final local suite passed
707 tests and the separate XeLaTeX integration suite passed 35 tests. Old
Hieropy API names in tests were replaced with the native parser API. Tests that previously monkeypatched
Hieropy internals now assert native parsing still works with the `hieropy`
module blocked.

The six-page 0.7 showcase uses the same three font binaries as the 0.6 baseline.
At 100 dpi, raster differences are confined to the version heading and the
page-five Unicode data label. Every page was visually inspected.

## Unicode and external test fonts

Generated `ROTATIONS`, `NO_MIRROR`, and `NO_ROTATE` tables come from
checksum-pinned official Unicode 18.0.0 `StandardizedVariants.txt` and
`Unikemet.txt`; the generated diff from 17.0.0 changes only the version
constant. See [UAX #57 revision 6](https://www.unicode.org/reports/tr57/tr57-6.html).
CI regenerates and checks the file. The Unicode data license is shipped with
the wheel.

Noto Sans Egyptian Hieroglyphs is downloaded by `scripts/fetch_noto.py`
from the official Noto repository. NewGardiner is downloaded by
`scripts/fetch_newgardiner.py` from the official
[nederhof/newgardiner](https://github.com/nederhof/newgardiner) revision
`e9334aaff65e0543a4b5d3a362fb5262043b2dd5`. Its SHA-256 is
`3c7710d6f7bb8cf791699c08f0cc453de5a9b6a12278ce3d727129163259f79d`,
matching the former 0.6 reference font exactly. Both downloads verify SHA-256.
Segoe UI Historic is a local optional Windows input. No external font enters
the XSR wheel.

## Installation and scope

The only direct normal runtime dependencies are fontTools (MIT) and Pillow
(MIT-CMU); XSR source is MIT. Hieropy is absent from runtime imports,
`[project].dependencies`, and the fresh-install CI environment. An isolated
wheel build and fresh venv installation verified that `import xsr`, native
parsing, and Egyptian rendering work without Hieropy; the wheel contains
Unicode data/license but no test fonts or caches.

Parsing 4,000 plain signs 200 times took 3.09 seconds on the local Windows
Python 3.11 run (roughly 15 ms per run); normal showcase runs are much shorter.
This is a measurement, not a timing assertion in CI.

Full vertical text flow and contextual GSUB insertion alternates remain
deliberately unsupported. The Noto optical insertion-placement question is
outside 0.7 scope. See the historical
[0.6 support audit](v0.6-verification.md) for other font limits.
