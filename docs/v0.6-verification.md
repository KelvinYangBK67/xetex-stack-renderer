The initial no-isolation wheel attempt failed because this machine's old system

During visual review, Segoe's D52 cmap entry rendered a font-supplied placeholder.
The showcase uses the registered H6 + FE03 variant instead. No font-specific code
or fallback was introduced. A font can contain placeholder outlines under valid
cmap entries, which cannot generally be distinguished from geometric Egyptian signs.

The showcase builder now owns a fresh renderer cache inside each fresh build
directory, so a PDF cannot accidentally reuse development-era cached responses.

## Correctness coverage

All 142 registered Egyptian rotation pairs are tested through the parser. Tests
also exercise all four NoMirror signs and 44 NoRotate signs, multiple FE03 angles,
unregistered pairs, high selectors, and the specific-variant precedence rule.
Geometry-only tests retain arbitrary-angle transform coverage independently of
which angles are legal Unicode encodings.

Cross-font tests cover all seven RTL insertion relations, nested H/V ordering,
rotation plus explicit mirror, open/damaged/alternate enclosure caps, empty
enclosures, ordinary/continuous/mixed lost shading, all five bracket families,
consecutive nested and unbalanced editorial brackets, and redundant singleton
segments. Direction participates in cache identity. Existing metric, outline,
synthetic-font, insertion collision, parser-isolation, path and cache tests remain.

XeLaTeX tests extract glyph positions from wrapped PDF paragraphs to verify that
H quadrats stay intact and each line follows the selected direction. They also
check exact short-run width, explicit editorial context without punctuation
hijacking, reserved vertical-mode errors, semantic diagnostics, multi-font RTL
preprocessing, font embedding and all prior protocol failure cases.

## Audit of 0.5 rejection branches

| Previous case | 0.6 disposition |
| --- | --- |
| Continuous lost sign + VS | FE00 implemented; other selectors explicitly rejected |
| Damaged enclosure delimiters | All 15 quadrant masks implemented |
| Additional enclosure caps | All parser-listed plain/walled endpoints supported; nonbasic shapes use selected-font outlines |
| Missing enclosure ends | Retained and direction-aware; no invented closing cap |
| Empty enclosure | Implemented as a blank quadrat inside the enclosure |
| BracketOpen / BracketClose parser nodes | Vector editorial marks; explicit host context keeps ordinary punctuation unchanged |
| Redundant singleton segment | Normalized before parsing; H/V precedence is retained |
| Consecutive editorial brackets | Preserved by a narrow parser-boundary normalization |
| Universal variation-selector angle | Removed; generated sign + selector mapping replaces it |
| Unbreakable top-level run | Atomic quadrat boxes with legal TeX breaks |
| Horizontal-only assumption | Explicit LTR/RTL; full vertical mode reserved and rejected |

Remaining rejection branches have specific reasons:

- Mismatched enclosure controls and endpoint/control families are invalid structure.
- Unknown parser/node/decoration types are defensive guards, not silently ignored controls.
- Empty runs/groups have no drawable geometry. Empty enclosures are handled separately.
- Reserved or unrecognized controls, misplaced joiners/modifiers and malformed grammar
  produce `XSR-PARSE`; there is no claim to render invalid Unicode sequences.
- Unregistered sign + VS pairs have no registered angle and are not guessed.
- NoMirror or prohibited NoRotate transformations change encoded identity.
- Insertion without sufficient default-outline space still fails explicitly.
- Full vertical text flow is deferred for future IMPE integration. V JOINER within
  a quadrat is supported in both horizontal directions.

The public editorial API accepts literal Unicode in `\xsrEgyptianText{...}`;
it deliberately does not expand arbitrary TeX macros or activate ASCII brackets
and grouping braces globally. Hosts can also dispatch a complete run directly.

## Unicode policy and maintainability

`generate_unicode_data.py` reads the official Unicode 17 StandardizedVariants and
Unikemet files, verifies SHA-256, and produces a compact Python table. CI checks
that regeneration matches the committed file. The source files remain ignored;
the generated module and Unicode license ship with the package.

Angles marked approximate use Unicode's stated representative angle. Specific
registered variants take precedence over broad NoRotate data: Unicode 17 includes
registered rotations for both U+131B1 (M003) and U+13371 (V006), despite their
NoRotate property. Other NoRotate requests fail. NoMirror applies to explicit
U+13440, independently of base-direction orientation. Provisional legacy/core
classifications do not trigger speculative warnings or automatic substitutions.

The README links the authoritative Unicode data, chapter 11, and UAX #57 revision 5.
The proposed Unicode 18 update was not used as the release data source.

## Contextual alternates and architecture

This remains deferred. The tested Noto and NewGardiner files have no GSUB table.
Segoe has substitutions for other scripts, but no generic metadata that identifies
an Egyptian insertion cavity. Feature names alone cannot select a safe alternate;
font-specific guesses would violate the selected-font geometry contract. A future
implementation must select, measure and render exactly the same glyph identity.

The generic core and active detector receive version changes only. Egyptian
semantics, direction, brackets and drawing remain in the backend. The Egyptian
registration extends contextual variation suffix detection through FE0F so an
unregistered selector receives a diagnostic instead of escaping into ambient text.
Python's minimum version is now consistently 3.11 in metadata, docs and CI.

## CI

The existing Ubuntu 24.04 workflow retains fresh installation, checksum-verified
Noto download, full pytest including XeLaTeX, cold-cache showcase rebuild, PDF
sanity checks and artifact upload. It additionally verifies generated Unicode data.
Segoe and native Windows paths are optional/platform-specific, not Linux requirements.
The completed commit's actual run is linked in the final report and repository Actions.
