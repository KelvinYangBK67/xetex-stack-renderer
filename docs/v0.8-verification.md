## Unicode basis

The implementation follows [Unicode 18 chapter 18, section 18.12](https://www.unicode.org/versions/Unicode18.0.0/core-spec/chapter-18/),
the [Unicode 18 KSS names list](https://www.unicode.org/Public/18.0.0/charts/nameslist/18b00/),
and the [Unicode KSS cluster proposal figures](https://www.unicode.org/L2/L2018/18121r-n4943-khitan-cluster.pdf).
The assigned signs are U+18B00..U+18CDA and U+18CFF; the intervening
U+18CDB..U+18CFE are unassigned. U+16FE4 immediately after the first sign
marks Type B. The older proposal's CGJ examples are not current Unicode
syntax. Normal consecutive signs form one cluster; U+0020 and U+200B separate
clusters. U+0020 is the recommended narrow visible separator; U+200B provides
a zero-width boundary. Unicode describes two-to-eight-sign phonograms,
single-sign units, left-to-right/top-to-bottom internal order, the iteration
mark U+18B00, unidentified sign U+18CFF, and upright clusters embedded in
horizontal text.

Type A starts with a left/right pair, continues in pairs, and centers an
unpaired final sign. Type B starts with one centered sign, continues with
left/right pairs, and centers an unpaired final sign. Both keep original
sign order. The parser rejects leading/trailing/repeated separators, misplaced
or repeated filler, isolated filler, and unassigned controls with typed XSR
errors. It does not expand the reading semantics of the iteration mark.

## Architecture and geometry

The new independent Khitan parser/model/layout/backend is under src/xsr/khitan.
The generic registry gained contextual infix ranges, and the active detector
gained a registered ordinary-space infix hook. Both retain SPACE only between
same-script KSS signs. The generic core maps string characters into request
codepoints so U+0020 survives. The renderer protocol and cache remain
script-neutral. The preprocessor discovers script-specific fonts and the
Khitan gap without mixing Egyptian profiles.

Khitan layout uses the selected font's advance and exact ink bounds. Its
stable one-em-or-larger slots are selected from Unicode structure, with ink
centering inside each slot. Placements contain translations and scale 1 only.
There is no KSS-specific GSUB lookup, font-name branch, raster search,
compression, rotation, or outline mutation. Each cluster is an atomic PGF box;
its full measured stack height is exposed to TeX, with depth 0 and a bottom
baseline. An eight-sign Type A cluster tested at four rows is at least 4 em
high; an eight-sign Type B cluster reaches five rows (5 em). A tall cluster enlarges its own line, and the following ordinary line
returns to normal baseline distance. Inter-cluster SPACE defaults to 0.2 em,
configurable through the Python cluster_gap option or TeX gap command;
U+200B uses zero gap. Both boundaries permit line breaking.

The architecture now accommodates two distinct models cleanly: Egyptian has
recursive syntax, adaptive geometry, insertion/overlay/enclosure and optional
compaction to a conventional line unit; Khitan has simple syntax, fixed
discrete slots, unscaled translation, and intrinsic vertical growth. Only
font measurement, run dispatch, response identity and rendering transport are
shared.

local Linear file is unavailable. The committed dual-font PDF has five pages;
every page was rendered and visually inspected. Neither font binary is tracked.

## Validation

- Baseline before changes: 707 total tests; 35 separate XeLaTeX tests; Egyptian showcase rebuilt.
- Final Khitan parser/geometry suite: 56 tests.
- Final Khitan XeLaTeX suite: 26 tests.
- Final full suite: 789 tests.
- Final separate XeLaTeX suites: 61 tests.
- Egyptian integration suite: 35 tests, unchanged and passing.
- Egyptian six-page showcase and both Khitan showcase variants rebuild.
- A clean 0.8 wheel was built and installed into a fresh virtual environment.
- Unicode semantics regeneration check and git diff whitespace check pass.
- GitHub Actions CI downloads the checksum-pinned Noto KSS font, rebuilds both
  showcase types, runs the complete and separate XeLaTeX suites, and rejects
  tracked external font binaries.

Intentional limits: full traditional vertical document flow is deferred;
variable/collection/webfonts are unsupported; Noto discretionary ligatures
and positional alternates are not reproduced; U+18CFF requires a selected
font with that outline; CI cannot reproduce the optional Linear comparison
page without the externally supplied Linear TTF.
