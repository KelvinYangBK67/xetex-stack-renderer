# v0.4.0 verification

Verified on 2026-10-03 with Python 3.11, Hieropy 0.1.4, fontTools 4.63.0,
XeTeX 0.999997 / TeX Live 2025, Poppler and PyMuPDF on Windows.

## Baseline

Before implementation, commit `8d28446` passed `python -m pytest`: **23 passed**,
including all **8 XeLaTeX integration tests**. No pre-existing test failures
were found. The baseline nested-H/V integration PDF was rendered and inspected;
it contained real NewGardiner glyphs. The baseline implementation measured with
Hieropy/NewGardiner while drawing with the ambient font.

All original test scenarios remain. Font setup was changed to the explicit
v0.4 API. Geometry assertions tied to NewGardiner's old numbers were replaced
with stronger font-derived measurements, centering, ordering and containment
checks, parameterized over the actual reference fonts.

## Final checks

- `python -m pytest`: **55 passed**, no failures or skips.
- `python -m pytest tests/test_tex_integration.py`: **14 integration cases**,
  covering the original eight cases plus all three reference fonts, scoped
  multi-font preprocessed rendering, rasterized ink containment and rejection
  of a stale font response.
- Synthetic TrueType fonts at 1000 and 2000 UPEM produce identical normalized
  geometry. Tests cover a negative left bearing, a descender, different advance
  and ink widths, missing/empty glyphs, bad paths/files, and file replacement
  invalidating the cache.
- A synthetic CFF OTF verifies cubic Bezier extrema (rather than control-point
  bounds) and normalized outline access. Real-font OTF integration has not been
  tested in this environment.
- Tests replace Hieropy `size` and `format` methods with failures and still lay
  out nested groups. All 12 showcase sequences satisfy nonoverlap and containment
  invariants in each reference font.
- A raster integration test measures a synthetic glyph's actual width/height in
  the PDF and confirms it sits within its framed layout box. It also guards
  against a trailing response-file newline adding interword space.
- `scripts/build_showcase.py` compiles without shell escape. The final PDF has
  **2 A4 pages**, 12 corresponding examples per font, and all three sign fonts
  embedded as subsets (`pdffonts`). Both pages were rendered with Poppler and
  visually inspected: no tofu, clipping, overlapping signs or blank sections.

The raster test requires PyMuPDF (`python -m pip install pymupdf`). The remaining
integration tests require XeLaTeX; embedding checks use `pdffonts` when present.
All of these tools were present for this verification.

## Deliverables and remaining limits

- Source: `examples/font-metrics-showcase.tex`
- Inspectable PDF: `examples/font-metrics-showcase.pdf`
- Rebuilder: `scripts/build_showcase.py`

Font selection is explicit and uses a restricted literal ASCII file path in the
TeX bridge. Static Unicode outline fonts are supported; variable instances and
font collections are rejected. Testing three real fonts plus synthetic metrics
is evidence for the generic path, not a guarantee about every Egyptian font.
NewGardiner's absent space glyph produces a font-loading warning; no missing
Egyptian glyph warnings were observed. Layout remains basic H/V packing with
no optical fitting, insertion, overlay, enclosures, mirroring, damage or rotation.
The parser grammar, line-breaking and preprocessing limits are documented in
README.md.
